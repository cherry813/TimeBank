# 管理员工作台说明

入口：`/admin`

演示账号：

```text
admin@campus.edu
123456
```

登录页也提供“管理员演示”快捷填充按钮。普通学生访问 `/admin`、`/admin/disputes` 或 `/admin/reports` 会被前端路由拦截，管理 API 还会再次查询数据库角色。

## 工作台模块

### 管理总览

- 待办总量、平台用户、活跃技能帖、完成订单和冻结时间币。
- 交易申诉与内容举报两个待办入口。
- 最新待办队列和最近 8 条管理员操作记录。
- API、数据库、自动确认任务和服务运行时间。

### 交易申诉

订单进入 `DISPUTED` 后，预约方、服务方都无法继续推进普通订单动作。管理员需要根据订单备注、申诉说明和时间币状态选择：

- `RELEASE`：完成订单，将冻结时间币结算给服务方。
- `REFUND`：取消订单，将冻结时间币退回预约方。

审核动作会写入订单事件时间轴，并向订单双方发送通知。

### 内容举报

举报对象可以为技能帖或用户。管理员根据举报说明选择：

- `DISMISS`：忽略举报。
- `CLOSE_LISTING`：关闭违规技能帖，写入审核下架标记。
- `WARN_USER`：记录用户举报处理结果并向用户发送提醒。

审核结果会通知举报人；关闭技能帖时还会通知内容所有者。

## 权限边界

管理员可以审核争议和处理违规内容，但不能直接修改用户时间币余额，也不能伪造订单完成状态。资金动作只能通过合法的订单状态动作或申诉审结触发。

被审核关闭的技能帖带有独立 `blocked_at` 标记，发布者不能通过编辑页或暂停/恢复功能绕过审核重新上架。

## 数据一致性

- 举报处理和技能帖下架在同一数据库事务中完成。
- 申诉结算或退款复用普通订单的结算和退款逻辑。
- 状态更新带有当前状态条件，重复审核会被拒绝。
- 投诉、审核、操作者、说明和时间均可在审计记录中查询。
